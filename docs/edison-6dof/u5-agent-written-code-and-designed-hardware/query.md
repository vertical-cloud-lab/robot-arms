Context. We run a small cloud lab at BYU (the Vertical Cloud Lab). Most remote work is done by AI coding agents: a GitHub comment starts an agent session in CI, which reaches a lab Raspberry Pi over SSH and drives the instrument (a gantry liquid handler, 3D printers, an AgileX PiPER 6-DOF arm with Raspberry Pi cameras and AprilTags); risky actions such as starting a print wait for a human approval, and every session, command and result is recorded in the repository. The lab ran about 575 agent sessions in 30 days across seven repositories. A recent proposal of ours asks whether a language-model agent can design and validate the connecting hardware of an automated alloy-development loop (sample holders, docking plates, camera mounts, grippers and fixtures, 3D-printed) and write the robot workflows around it, well enough that the loop runs with minimal human handling and full provenance. We have reproduced an agentic manipulation policy (Apple's AMP1, on the CaP-Gym benchmark) on a simulated PiPER; in simulation the agent measured and compensated joint deadbands on its own, but each task took minutes. We know of CaP-X/CaP-Gym, AMP1, ACE-CaP-0, WetRobo (a coding agent driving PiPER arms across two wet labs), Coscientist, CRESt, MATTERIX, LabSafety Bench and CADSmith.

Question.
(1) Agent-written robot code on physical laboratory hardware: which systems (2023 to 2026) have run language-model-generated code or plans on real lab robots or arms, with what measured success rates and trial counts, failure modes (unsafe or infeasible motions, wrong frames or units, hallucinated APIs, silent failures), latency and cost per task, and how often a human had to intervene?
(2) Safeguards: which verification layers have been shown to catch agent errors before or during execution (typed skill libraries, static checks, simulation or digital-twin dry runs, workspace and force limits, runtime monitors, vision-language verifiers, human approval gates), with measured catch rates and false-alarm rates? Is there evidence that freezing agent-written code once it works is more reliable than regenerating code for every run?
(3) Agent- or AI-designed physical hardware for laboratory robots: language-model or generative design of fixtures, holders, grippers, adapters or docking features that were then fabricated (for example 3D-printed) and tested on real hardware. Report first-pass fit or function rates, iterations to success, human edits needed, and how the designs were checked.
(4) Provenance and auditability for agent-operated laboratories: methods that link the request, the generated code or CAD, the commit, and the physical outcome (what was requested versus what physically happened), reproducibility of agent-run procedures across sites, and relevant standards (for example cybersecurity clauses in ISO 10218:2025 for networked robots).
(5) What would a defensible evaluation of "an agent designs the fixture and writes the workflow, and the arm runs it" look like: outcome metrics, baselines (human expert, scripted), sample sizes, and the failure rates the literature suggests we should expect?

Prefer peer-reviewed sources from 2015 to 2026, but include 2025 and 2026 preprints where they are the only evidence, flagged as preprints. For each claim give the DOI or arXiv ID and quote the sentence that supports it. Say explicitly where no published evidence exists.
